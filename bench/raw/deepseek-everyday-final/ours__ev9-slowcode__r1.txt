# Speeding Up Large CSV Processing in Python

Reading a 2 GB CSV can be slow with naive approaches. Here are the most effective strategies, from quick wins to more advanced techniques.

<Card title="Quick wins first" subtitle="Try these before rewriting anything">
<Steps>
<Step title="Use the right CSV reader" status="done" subtitle="~2-3× faster">
The built-in `csv` module is slow. Use **pandas** with the `engine='c'` (default) or **PyArrow** for a significant boost.
</Step>
<Step title="Skip unnecessary work" status="done" subtitle="~1.5-2× faster">
Only read the columns you need with `usecols`, and use `dtype` to avoid type inference overhead.
</Step>
<Step title="Process in chunks" status="done" subtitle="Constant memory usage">
Don't load the whole file at once. Read it in chunks so memory stays flat.
</Step>
</Steps>
</Card>

## 1. Use pandas properly

<Code file="pandas_fast.py" highlight="3 | 5-7">
```python
import pandas as pd

# Only read the columns you need
cols = ['date', 'user_id', 'amount', 'category']

df = pd.read_csv(
    'huge_file.csv',
    usecols=cols,                    # skip parsing unneeded columns
    dtype={'user_id': 'int32',        # smaller dtypes = less memory
           'amount': 'float32'},
    parse_dates=['date'],             # parse dates once, not later
    engine='c',                       # default, but explicit is nice
)
```
</Code>

<Callout tone="info" title="Memory tip">
If the file won't fit in RAM, use `chunksize` and process in batches:

```python
for chunk in pd.read_csv('huge_file.csv', chunksize=500_000):
    process(chunk)  # aggregate, filter, write out
```
</Callout>

## 2. Try Polars (fastest pure-Python option)

<Card title="Polars example" subtitle="Rust-backed, lazy evaluation, often 5-10× faster than pandas">
<Code file="polars_fast.py">
```python
import polars as pl

# Lazy API: only does the work you ask for
q = (
    pl.scan_csv('huge_file.csv')
    .select(['date', 'user_id', 'amount'])
    .filter(pl.col('amount') > 100)
    .group_by('user_id')
    .agg(pl.col('amount').sum())
)

result = q.collect()  # runs the query
```
</Code>
</Card>

## 3. Stream with the standard library (no dependencies)

<Card title="Chunked reading with csv" subtitle="When you can't install anything">
<Code file="streaming_csv.py">
```python
import csv
from collections import Counter

counts = Counter()
with open('huge_file.csv', newline='') as f:
    reader = csv.reader(f)
    header = next(reader)
    for row in reader:
        # Process one row at a time — memory stays tiny
        counts[row[3]] += 1

print(counts.most_common(10))
```
</Code>

<Callout tone="warning" title="What's slow here">
The `csv` module is pure Python. If you must use it, consider `csv.DictReader` only for readability, not speed. For 2 GB files, you'll feel the difference.
</Callout>
</Card>

## 4. Advanced: parallel processing

<Card title="Parallelize with multiprocessing" subtitle="Only if you have CPU cores to spare and the work is CPU-bound">
<Code file="parallel_csv.py">
```python
from multiprocessing import Pool
import pandas as pd

def process_chunk(path):
    # Each worker reads and processes its own slice
    df = pd.read_csv(path, chunksize=1_000_000)
    total = 0
    for chunk in df:
        total += chunk['amount'].sum()
    return total

if __name__ == '__main__':
    with Pool(4) as pool:  # 4 processes
        # Split the file into 4 ranges (requires seeking) or use a queue
        results = pool.map(process_chunk, ['huge.csv'] * 4)
        print(sum(results))
```
</Code>
</Callout>

<Callout tone="danger" title="Disk I/O is often the real bottleneck">
If the file is on a slow disk, no library will help. Consider:
- **Convert to Parquet** once — then reads are 10× faster
- Move the file to an SSD
- Compress with gzip (`pd.read_csv('file.csv.gz')`) — often *faster* due to less I/O

<Code file="convert_to_parquet.py">
```python
import pandas as pd

# One-time conversion
df = pd.read_csv('huge.csv')
df.to_parquet('huge.parquet', compression='snappy')

# Now reads are blazing fast
df = pd.read_parquet('huge.parquet')
```
</Code>
</Callout>

## Decision guide

<Compare title="Which approach for you?">
| Factor | pandas | Polars | csv module | Parquet |
|---|---|---|---|---|
| Speed | Good | Excellent | Poor | Excellent |
| Memory | High | Low | Tiny | Low |
| Learning curve | Easy | Moderate | Trivial | Easy |
| Setup | pip install pandas | pip install polars | Built-in | pip install pyarrow |
| Best for | Data analysis | Big files, queries | Simple scripts | Repeated reads |

<Columns>

</Card>
<Card title="If you must stay pure Python">
Stream with `csv.reader` and process row by row. It won't be fast, but it will finish without running out of memory.
