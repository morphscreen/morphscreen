# Speeding Up Large CSV Processing in Python

Reading a 2 GB CSV is memory-intensive and slow with the default approach. Here's how to make it dramatically faster.

<Callout tone="warning" title="Memory warning">
A 2 GB CSV can easily consume 3–4× its size in RAM when loaded as a DataFrame or list of dicts. Always profile memory alongside speed.
</Callout>

<Card title="First, identify the bottleneck">
Before optimizing, check what's actually slow:

<Columns>
<div>
**Reading the file** – I/O speed, format overhead  
**Parsing** – converting strings to numbers/dates  
**Memory allocation** – building lists/DataFrames  
**Processing** – the work you do on each row
</div>
<div>
<Code file="profile.py">
import time
import pandas as pd

start = time.time()
df = pd.read_csv("large.csv")
print(f"Read: {time.time() - start:.2f}s")

start = time.time()
# your processing here
print(f"Process: {time.time() - start:.2f}s")
</Code>
</div>
</Columns>
</Card>

<Card title="Top strategies, in order of impact">
<Steps>
<Step title="Use a faster reader" status="done">
**Pandas with `engine='pyarrow'`** (if installed) or **Polars** – often 5–10× faster than default C engine for large files.
</Step>
<Step title="Read only what you need" status="done">
Skip columns with `usecols`, filter rows with `nrows` or `chunksize`. Don't load the whole file if you only need a subset.
</Step>
<Step title="Specify dtypes" status="done">
Tell pandas the types upfront – it won't have to guess, which saves massive time on parsing.
</Step>
<Step title="Process in chunks" status="done">
For memory-bound work, read and process the file in blocks instead of all at once.
</Step>
<Step title="Consider going parallel" status="done">
For CPU-heavy processing, use `multiprocessing` or `polars`' optimized paths.
</Step>
</Steps>
</Card>

<Card title="The fastest practical approach">
<Columns>
<div>
**Option A: Polars** (Rust-based, fastest for most cases)
</div>
<div>
<Code file="polars_example.py">
import polars as pl

# Lazy API – only computes what you need
df = pl.scan_csv("large.csv", infer_schema_length=1000)
# Chain operations lazily
result = (df.filter(pl.col("age") > 30)
            .group_by("city")
            .agg(pl.col("amount").sum())
            .collect())  # Execute now
</Code>
</div>
</Columns>

<Columns>
<div>
**Option B: Pandas with PyArrow**
</div>
<div>
<Code file="pandas_arrow.py">
import pandas as pd

df = pd.read_csv(
    "large.csv",
    engine="pyarrow",          # faster parsing
    dtype_backend="pyarrow",   # memory-efficient types
    usecols=["id", "name", "amount"],  # only needed columns
    parse_dates=["date"],
)
</Code>
</div>
</Columns>
</Card>

<Card title="Chunked processing (memory-friendly)">
<Code file="chunked.py">
import pandas as pd

chunk_size = 500_000
results = []

for chunk in pd.read_csv("large.csv", chunksize=chunk_size):
    # Process each chunk
    chunk["total"] = chunk["quantity"] * chunk["price"]
    results.append(chunk.groupby("category")["total"].sum())

# Combine partial results
final = pd.concat(results).groupby(level=0).sum()
</Code>
</Callout>

<Callout tone="info" title="When to use what">
- **File is 2–5 GB, memory is plentiful** → Polars lazy API or pandas with PyArrow  
- **File is bigger than RAM** → Chunked reading, or use a database (SQLite, DuckDB)  
- **You need SQL-like queries** → DuckDB reads CSVs directly and is extremely fast  
- **You're doing complex transformations** → Polars in lazy mode, or pandas with vectorized ops
</Callout>

<Card title="Additional micro-optimizations">
- **Use `numpy` for pure numeric columns**: `np.loadtxt` or `np.genfromtxt` are faster than pandas for homogeneous data.  
- **Set `low_memory=False`** in pandas to avoid mixed-type inference issues.  
- **Compress the file**: a `.csv.gz` is often 5–10× smaller; pandas reads it just as fast (the decompression is cheap).  
- **Use `cudf`** if you have an NVIDIA GPU – it can be 50–100× faster, but requires GPU setup.  
- **Avoid `apply` with Python functions** – vectorize with numpy/pandas operations instead.
</Card>

<Card title="If you can change the file format">
<Callout tone="success" title="Best long-term fix">
Convert your CSV to **Parquet** once, then all future reads are 10–20× faster and use 5–10× less memory. Parquet stores columnar data with compression and type information.
</Callout>
<Code file="convert_to_parquet.py">
import pandas as pd

# One-time conversion
df = pd.read_csv("large.csv", engine="pyarrow")
df.to_parquet("large.parquet", compression="snappy")

# Then read instantly
df = pd.read_parquet("large.parquet")
</Code>
