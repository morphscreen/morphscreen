## 2. The Fastest Simple Solution: Pandas with Chunking

<Card title="Chunked reading example">
If you're currently doing something like this:

<Code file="slow.py">
```python
import csv
with open('large.csv') as f:
    reader = csv.reader(f)
    data = [row for row in reader]
```
</Code>

Switch to this:

<Code file="fast.py" highlight="3-6">
```python
import pandas as pd

chunksize = 100_000  # adjust based on your RAM
for chunk in pd.read_csv('large.csv', chunksize=chunksize):
    # Process each chunk here
    # e.g., filter, aggregate, or write to another file
    processed = chunk[chunk['value'] > 100]
    processed.to_csv('output.csv', mode='a', header=False)
```
</Code>

<Callout tone="success" title="Why this works">
- Pandas uses C-optimized parsing (much faster than Python loops)
- Chunking keeps memory usage under control
- You can process the file in parallel batches
</Callout>
</Card>

## 3. Optimize Your Current Approach

<Card title="If you must use pure Python">
<Steps>
<Step title="Use csv module instead of manual parsing" status="done">
The csv module is C-optimized and handles edge cases automatically.
</Step>
<Step title="Avoid building large lists" status="done">
Process rows one at a time instead of collecting them all.
</Step>
<Step title="Use generators" status="done">
Yield rows instead of returning a list to avoid memory spikes.

## 4. Memory and Performance Tuning

<Card title="Pandas read_csv parameters that matter">
<KeyValue title="Key parameters">
| Parameter | Effect |
|---|---|
| `dtype` | Specify column types to avoid guessing (up to 2x faster) |
| `usecols` | Only read columns you need |
| `low_memory=False` | Read whole file at once (if RAM allows) |
| `engine='c'` | Default; use 'pyarrow' for even better performance |
| `parse_dates` | Pre-parse date columns |
</KeyValue>

<Code file="optimized.py">
```python
import pandas as pd

# Specify dtypes to avoid type inference overhead
dtypes = {
    'id': 'int32',
    'name': 'object',
    'value': 'float32',
    'date': 'object'  # parse separately if needed
}

df = pd.read_csv(
    'large.csv',
    dtype=dtypes,
    usecols=['id', 'name', 'value'],  # only needed columns
    parse_dates=['date'],
    engine='pyarrow'  # if you have pyarrow installed
)
```
</Code>
</Card>

## 5. Parallel Processing

<Card title="Process chunks in parallel">
If you have a multi-core machine, process chunks concurrently:

<Code file="parallel.py">
```python
from multiprocessing import Pool
import pandas as pd

def process_chunk(chunk):
    # Your processing logic here
    return chunk[chunk['value'] > 100]

if __name__ == '__main__':
    chunks = pd.read_csv('large.csv', chunksize=100_000)
    
    with Pool(4) as pool:  # Use number of CPU cores
        results = pool.map(process_chunk, chunks)
    
    # Combine results
    final = pd.concat(results)
```
</Callout>

<Callout tone="warning" title="Memory warning">
Parallel processing uses more memory. If your system has less than 16 GB RAM, stick with sequential chunking.
</Callout>
</Card>
