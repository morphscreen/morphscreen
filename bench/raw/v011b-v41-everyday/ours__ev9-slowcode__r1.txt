# Speeding up a 2 GB CSV read in Python

The usual culprit is doing too much in pure Python per row. The fix is almost always: **push the work into C (pandas/polars/pyarrow), read in chunks, and only keep what you need.**

<Card title="The short answer">
- **pandas `read_csv`** with `dtype`, `usecols`, `engine="c"` — 5–20× faster than a Python loop.
- **Polars** (`pl.read_csv`) — often 3–10× faster than pandas, and lower memory.
- **PyArrow** (`pyarrow.csv.read_csv`) — fastest raw parse, zero-copy to Arrow.
- **Chunked reading** (`chunksize=` or `csv.reader` in a generator) if you can't fit it in RAM.
- **Drop `csv.DictReader`** — dict-per-row is the slowest common pattern.
</Card>

<Card title="Where the time actually goes">

## 1. Stop using `csv.DictReader` in a loop

<Diff file="before_after.py">
- import csv
- with open("big.csv") as f:
-     for row in csv.DictReader(f):
-         total += float(row["amount"])
+ import polars as pl
+ df = pl.read_csv("big.csv", columns=["amount"])
+ total = df["amount"].sum()
</Diff>

## 2. Tune `read_csv` if you're staying on pandas

<Card title="pandas read_csv checklist">
<Checklist title="Tuning steps" name="pandas-tuning">
- [x] Pass `usecols=[...]` — never load columns you won't use
- [x] Pass `dtype={...}` — avoid object columns and float upcasting
- [x] Use `engine="c"` (default) — never `engine="python"`
- [ ] Try `parse_dates=["date"]` instead of post-hoc `to_datetime`
- [ ] Set `low_memory=False` to avoid chunked re-inference
- [ ] Consider `pyarrow` engine: `engine="pyarrow"` (pandas ≥ 2.0)
- [ ] If memory-bound, add `chunksize=500_000` and process per chunk
</Checklist>
</Card>

<Card title="A tuned read">
<Code file="fast_read.py">
import pandas as pd

dtypes = {"id": "int64", "amount": "float32", "category": "category"}

df = pd.read_csv(
    "big.csv",
    usecols=["id", "amount", "category", "date"],
    dtype=dtypes,
    parse_dates=["date"],
    engine="pyarrow",      # falls back to "c" if unavailable
)

total = df["amount"].sum()
</Code>
</Card>

## 3. If it doesn't fit in memory, stream it

<Card title="Chunked aggregation">
<Code file="chunked.py">
import pandas as pd

total = 0.0
for chunk in pd.read_csv(
    "big.csv",
    usecols=["amount"],
    dtype={"amount": "float32"},
    chunksize=1_000_000,
):
    total += chunk["amount"].sum()

print(total)
</Code>
Chunks keep peak memory at ~one chunk instead of the whole file. Works with `csv.reader` too, but pandas chunks are far faster.
</Card>

<Callout tone="info" title="Convert once, read many">
If you'll read this file more than a couple of times, convert it once to **Parquet** (`df.to_parquet(...)`). Subsequent reads are typically 5–20× faster and 2–5× smaller on disk, because Parquet is columnar and typed.
</Callout>
