# Speeding up reading a 2 GB CSV in Python

Reading a 2 GB CSV can be painfully slow if you're using the default `csv.reader` or `pandas.read_csv()` without optimizations. Here's how to make it dramatically faster.

<Card title="Why it's slow" subtitle="Common bottlenecks">
<Columns>
<div>
**Default approaches:**

- `csv.reader` in pure Python — very slow
- `pandas.read_csv()` with default settings — memory-heavy
- Reading line-by-line in a loop — no parallelism
- No type hints — pandas guesses column types (expensive)
</div>
<div>
**What actually helps:**

- Use `pandas` with `engine="c"` (default) and `nrows` for testing
- Specify `dtypes` to avoid type inference
- Use `chunksize` for memory efficiency
- Consider `polars` or `duckdb` for large files
- Use parallel processing with `multiprocessing`
</div>
</Columns>
</Card>

## 1. Quick win: optimize pandas

<Card title="Fastest pandas approach">
<Code file="optimized_read.py" highlight="1 | 3">
import pandas as pd

# Specify dtypes to skip inference (big speedup)
dtypes = {
    'column_a': 'int32',
    'column_b': 'float32',
    'column_c': 'category',
    'column_d': 'str'
}

# Read in chunks to avoid memory blowup
chunks = []
for chunk in pd.read_csv(
    'large_file.csv',
    dtype=dtypes,
    chunksize=500_000,
    low_memory=False,   # Avoid mixed-type warnings
    usecols=['column_a', 'column_b', 'column_c', 'column_d'],  # Only needed columns
    parse_dates=['date_column']  # Parse dates efficiently
):
    chunks.append(chunk)

df = pd.concat(chunks, ignore_index=True)
</Code>
<Callout tone="info" title="Why this helps">
- **dtype** — pandas skips expensive type inference
- **chunksize** — keeps memory low, lets you process incrementally
- **usecols** — only loads the columns you need
- **low_memory=False** — reads whole file at once (faster, more RAM)
</Callout>
</Card>

## 2. Try Polars (5–10x faster)

<Card title="Polars: the modern alternative">
<Code file="polars_read.py">
import polars as pl

# Polars is multithreaded by default
df = pl.read_csv(
    'large_file.csv',
    dtypes={'column_a': pl.Int32, 'column_b': pl.Float32},
    try_parse_dates=True
)

# For lazy evaluation (only loads what you need):
lazy_df = pl.scan_csv('large_file.csv')
result = lazy_df.filter(pl.col('column_a') > 100).collect()
</Code>
<Callout tone="success" title="Why Polars wins">
- Built-in parallelism (uses all CPU cores)
- Columnar memory layout
- Lazy evaluation for filtering before loading
- Often 5–10x faster than pandas
</Callout>
</Card>

## 3. DuckDB: SQL power for CSVs

<Card title="DuckDB — query without loading">
<Code file="duckdb_read.py">
import duckdb

# Query the CSV directly, no full load needed
result = duckdb.sql("""
    SELECT column_a, COUNT(*)
    FROM 'large_file.csv'
    WHERE column_b > 50
    GROUP BY column_a
""").df()

# Or load once, query many times
con = duckdb.connect()
con.execute("CREATE TABLE data AS SELECT * FROM 'large_file.csv'")
df = con.execute("SELECT * FROM data WHERE column_a > 100").df()
</Code>
<Callout tone="info" title="Best for">
- Filtering/aggregating large CSVs
- Joining with other data sources
- When you don't need the entire file in memory
</Callout>
</Card>

## 4. Parallel processing with multiprocessing

<Card title="Split and parallelize">
<Code file="parallel_read.py">
import pandas as pd
from multiprocessing import Pool
import numpy as np

def read_chunk(args):
    file, skiprows, nrows = args
    return pd.read_csv(file, skiprows=skiprows, nrows=nrows, header=None)

# Count lines first (fast with wc -l or a quick scan)
n_lines = sum(1 for _ in open('large_file.csv')) - 1  # minus header
n_workers = 4
chunk_size = n_lines // n_workers

args = []
for i in range(n_workers):
    skip = 1 + i * chunk_size  # skip header + previous chunks
    args.append(('large_file.csv', skip, chunk_size))

with Pool(n_workers) as pool:
    dfs = pool.map(read_chunk, args)

df = pd.concat(dfs, ignore_index=True)
</Code>
<Callout tone="warning" title="Caveat">
- Must know the header and line count
- Parallel read can be slower for small files (overhead)
- Works best on SSDs with multiple cores
</Callout>
</Card>

## 5. Memory-mapped file (for very large files)

<Card title="Numpy memory mapping">
<Code file="memmap_read.py">
import numpy as np
import pandas as pd

# For numeric data, map the file without loading it
mmap = np.memmap('large_binary.dat', dtype='float32', mode='r')
# If you need CSV, convert once to binary format first:
df = pd.read_csv('large_file.csv', usecols=['numeric_col'])
df.to_pickle('cached.pkl')  # Then load in milliseconds later

# Fast reload:
df = pd.read_pickle('cached.pkl')
</Code>
<Callout tone="info" title="Pro tip">
If you read the same CSV multiple times, convert it to **Parquet** or **pickle** once. Reloading is 10–100x faster.
</Callout>
</Card>
