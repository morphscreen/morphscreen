# Code Review: Bug Fix for User Authentication Token Refresh

<Card title="Bug Report" subtitle="Issue #AUTH-247">
## Problem
Users are being logged out unexpectedly after 15 minutes of inactivity, even when the "Remember me" option is selected during login.

## Root Cause
The token refresh logic in `authService.ts` incorrectly calculates the refresh threshold. It uses `expiresIn - 300` (5 minutes) as the refresh window, but the JWT tokens issued by our backend have a 15-minute expiry with no refresh token rotation. This means tokens expire before the refresh attempt fires.

## Impact
- **Affected users**: All users with "Remember me" enabled (~68% of active sessions)
- **Frequency**: Every 15 minutes of inactivity
- **Workaround**: Manual re-login required

## Test Scenarios

### 1. Standard Session (No "Remember me")
1. Log in **without** checking "Remember me"
2. Wait 4 minutes (within 5-min threshold)
3. Verify token refresh API call fires automatically
4. Confirm session continues without interruption

### 2. "Remember me" Session — Primary Fix
1. Log in **with** "Remember me" checked
2. Wait 14 minutes (within new 15-min threshold)
3. Verify silent re-authentication occurs
4. Confirm user stays logged in
5. Wait 20 minutes total — verify re-auth happens again

### 3. Edge Cases
| Scenario | Expected Behavior |
|---|---|
| Network failure during silent re-auth | Show toast, keep session alive for retry |
| Cached credentials cleared manually | Redirect to login page |
| Token already expired on app load | Immediate silent re-auth attempt |
| Multiple tabs open | Only one tab performs re-auth (lock mechanism) |

### 4. Regression Checks
- [ ] Standard login still works
- [ ] Logout clears all cached credentials
- [ ] Password change invalidates "Remember me" sessions
- [ ] Session expiry handling on mobile background/foreground
